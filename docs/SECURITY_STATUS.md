# Security verification status — 2026-07-21

`npm run check` compiles five Solidity sources with solc 0.8.30 (Shanghai target), strictly type-checks TypeScript, syntax-checks the Intelligent Contract safety boundary, and runs fifteen tests. Covered invariants include two distinct agreeing RPC providers, source receipt success, configured EndpointV2 `PacketSent`, block identity, confirmation depth, canonical PacketV1 version/nonce/EIDs/sender/receiver/GUID/message/payload-hash recomputation, HTTPS/fresh/digested evidence, complete GenLayer submission bindings, rejection of pre-final states and failed finalized execution, finalized record binding, no signing before finalized allow, GUID idempotency, signer quorum/order, execution-domain binding, target failure rollback, OApp quote/send/receive, trusted peers, target allowlisting, authorization replay and GUID replay.

Not covered: real EndpointV2/ULN302 receive-library calls, reorg polling, live GenLayer Studio/testnet compatibility, validator variance and web-render stability, durable coordinator storage, authenticated signer transport, key custody, five failure domains, fuzzing, Solidity static analysis, formal verification or third-party audit. `MockEndpointV2` matches the OApp-facing ABI and official packet encoding needed by these tests but is not a security model of the LayerZero endpoint. The Intelligent Contract checker is syntax/guardrail validation, not GenVM execution.

The installed development tree reports advisories inherited primarily through Ganache and LayerZero build-time tooling. These packages are not runtime coordinator dependencies; `npm ls --omit=dev` contains only ethers 6.17.0 and its runtime tree. This distinction does not waive the findings: replace or isolate affected test tooling before CI handles untrusted artifacts, and rerun audits whenever locks change.
