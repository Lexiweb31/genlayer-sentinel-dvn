# Security verification status — 2026-07-22

`npm run check` compiles five Solidity sources with solc 0.8.30 (Shanghai target), strictly type-checks TypeScript, syntax-checks the Intelligent Contract safety boundary, and runs 104 tests. Coverage includes packet, policy, signer, adapter, OApp, listener and API invariants plus the isolated Hardhat EDR lifecycle; exact GenLayer JSON-RPC correlation and the strict `FINALIZED`/`7`/successful-execution/`latest-final` gate; exact destination-manifest validation; two-provider chain/block agreement; pinned Endpoint/receive-library/ULN/OApp/adapter state; canonical PacketV1 header and ULN302 calldata reconstruction; immutable `SIGNING` intent before signer contact; exact authorized 3-of-5 share persistence; restart reconciliation without duplicate signing; path revalidation before submission; intent-before-broadcast ordering; ambiguous-attempt no-rebroadcast behavior; independent receipt/block/event/used-state confirmation; bounded ingestion quarantine; and safe packet requeue. The end-to-end slice deploys real adapter bytecode, uses five ephemeral ECDSA signer services, executes an allowed action and proves that denial produces no signer or destination activity.

Not covered: a standalone daemon or approved account provider; live EndpointV2/ULN302 calls; proof that configured RPC origins are independently operated; atomic state proofs across the destination path reads; live-chain receipt/reorg polling; destination nonce/fee replacement management; authenticated ambiguous-attempt recovery; distributed exactly-once delivery; retry backoff; live GenLayer Studio/testnet compatibility; validator variance and web-render stability; multi-node coordinator storage; production mutual TLS/certificate lifecycle; key custody; five independent signer failure domains; rate limiting; fuzzing; Solidity static analysis; formal verification or third-party audit. `MockEndpointV2` and `MockVerificationTarget` expose only the narrow official/test ABIs required by the local tests and are not security models of LayerZero. The Intelligent Contract checker is syntax/guardrail validation, not GenVM execution.

The 2026-07-22 registry audit reports **zero production advisories** across the ten-node production tree from `npm audit --omit=dev`. The complete development tree reports 19 advisory nodes: 13 low, 2 moderate, 4 high and 0 critical. Archived Ganache and its bundled native fallback tree are gone. Remaining paths are Hardhat `3.10.0` through `adm-zip`, the local `solc` wrapper through `tmp`, and LayerZero's development-only ethers 5 tree through packages including `elliptic` and `ws`. These tools are not shipped in the coordinator runtime, but that distinction does not waive the findings. Hardhat is restricted to reviewed local test artifacts and a loopback EDR server; compiler input remains limited to reviewed repository sources, and audits must be rerun whenever the lock changes.

`npm ls --omit=dev --depth=2` exits zero and contains only Sentinel's pinned ethers 6 runtime tree. GenLayerJS was removed because production source used it only for enums; Sentinel now owns the small read-only status protocol and keeps account-aware submission/contract reads behind an injected interface. Hardhat is an exact development dependency and is not production-reachable. The version `0.22.0` lock is normalized with pinned npm 10.9.2. `contracts/src` is unchanged in this milestone; the added mock target is test-only. Production adapter/OApp artifact hashes remain identical to `main` after recompilation.

Do not run `npm audit fix` blindly. The registry currently suggests semantically unsafe downgrades such as Hardhat 0.0.7 and solc 0.5.0. The complete evidence and upgrade gates are in [`research/2026-07-22-dependency-audit.md`](research/2026-07-22-dependency-audit.md).
