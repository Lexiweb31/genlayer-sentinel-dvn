# Threat model and trust assumptions

Protected assets are DVN signing authority, policy integrity, packet/evidence bindings, and operator truthfulness. Attackers may control one RPC, coordinator instances, dashboard inputs, evidence hosting, TLS endpoints, or fewer than the signer threshold; reorder/replay requests; duplicate one signer identity behind several URLs; induce reorgs; or exploit semantic ambiguity.

Controls: two-provider agreement plus confirmation depth; canonical hash recomputation; immutable per-GUID request binding; strict ABI/allowlist checks before semantic review; evidence content digest and freshness window; finalized (not merely accepted) GenLayer state; domain-separated signing payload with chain, adapter, GUID, decision and expiry; canonical versioned signer requests; mutual-TLS/SPKI identity pinning at the deployment boundary; durable request replay and conflicting-GUID rejection before signing; unique authorized signer-address recovery and on-chain used-digest tracking; idempotent state transitions; key isolation behind signer-provider interfaces; independent required/optional LayerZero DVNs.

Residual risks: GenLayer validator/model correlation, governance source compromise, both source or destination RPCs lying consistently, destination chain/account/nonce failure, signer implementation or certificate-authority compromise, stale/unrotated pins, multiple nominal operators under common control, LayerZero or adapter bugs, finality/API interpretation errors, reservation-triggered denial of service, ambiguous transaction broadcast, fee volatility, and general signer unavailability. Intent-before-broadcast prevents unsafe automatic replay but can create false-positive manual recovery incidents after a crash before broadcast. A semantic `ALLOW` is not proof of source-chain inclusion. A deterministic pass is not governance authorization. Injected transport tests are not evidence that production custody, mutual TLS or independent failure domains exist.

Rollback: pause job intake and signer issuance; remove Sentinel from optional DVNs using OApp owner governance; rotate signers by threshold-authorized adapter update; never rewrite finalized decisions; deploy a new policy version and explicitly migrate future GUIDs. Already executed cross-chain actions are not reversible by Sentinel.
