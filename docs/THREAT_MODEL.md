# Threat model and trust assumptions

Protected assets are DVN signing authority, recovery authority, policy integrity, packet/evidence bindings, wallet intent, destination execution, audit history, and operator truthfulness. Attackers may control one RPC, coordinator instances, dashboard inputs, evidence hosting, TLS endpoints, fewer than either threshold, or privileged SQLite access; reorder/replay requests; duplicate one signer/operator identity behind several endpoints; induce reorgs; exploit semantic ambiguity; inject a malicious wallet/provider; switch accounts or chains after quoting; replace or revert a source transaction; spoof a GUID in browser state; race runtime shutdown and recovery; truncate or recompute a local audit chain; misrepresent fixtures as decentralized consensus; or expose a loopback service beyond its intended host.

Controls: two-provider agreement plus confirmation depth; canonical hash recomputation; exact historical packet-block agreement; explicit source send library, raw ULN, executor, peer and bytecode checks; persisted nonzero source-configuration digest; rejection of destination ULN values inherited from defaults; immutable per-GUID request binding; strict ABI/allowlist checks before semantic review; evidence content digest and freshness window; finalized (not merely accepted) GenLayer state; domain-separated DVN signing payload with chain, adapter, GUID, decision and expiry; canonical bounded `sentinel-signer/v2` requests; durable coordinator construction of a GenLayer transaction/evidence/action/policy witness; signer-side verification of `FINALIZED`/`7`, exact successful `evaluate` arguments and the strict immutable record; native TLS 1.3 mutual authentication with explicit CA roots, logical-host verification and live canonical-DER SPKI pins; strict request/response framing and bounded shutdown; durable request replay and permanent execution-plus-authorization digest binding before signing; unique authorized signer-address recovery and on-chain used-digest tracking; idempotent state transitions; key isolation behind signer-provider interfaces; independent required/optional LayerZero DVNs. The coordinator publishes only a closed-schema, same-process runtime observation over a GET-only endpoint: exact lifecycle and lease relationship, bounded phase/outcome and sanitized timestamps, with no lease owner or raw exception. Contradictory states fail closed, and detected lease loss permanently stops normal work until process restart. The Intelligent Contract separately enforces 32-byte GUID/packet/evidence hashes, credential-free HTTPS, UTF-8 byte bounds, coordinator-only evaluation, JSON framing of semantic inputs as untrusted data, evidence-digest verification before LLM execution, strict fail-closed answer normalization, and one immutable structured `DECIDED` record per GUID. The record stores action, policy and request-binding digests; a domain-separated, byte-length-prefixed Python/TypeScript vector binds the exact packet, evidence, action, policy and version across the GenLayer/coordinator boundary. Recovery adds a separate five-operator council and exact three-signature EIP-712 quorum; deployment-domain salt; kind/state/failure/candidate/precondition binding; a minimum 15-minute delay and bounded lifetime; a durable runtime/recovery mutex that requires explicit release; repeated deterministic source or destination proof; no destination submitter dependency; protected state change plus hash-chained receipt in one SQLite transaction; replay-stable receipts; sanitized error codes; and a read-only API/dashboard.

Local app controls: the demo capability is absent by default and accepted only for loopback HTTP, chain `31337`, one source OApp, one destination EID, one target, `record(bytes32)`, zero action value, empty options, native fee payment, and an explicitly labeled semantic fixture. The browser serializes wallet connection, rechecks chain ID and the OApp’s on-chain owner before quote and send, invalidates an in-flight quote on account/chain/input change without accepting a stale result, calls `eth_sendTransaction` exactly once, preserves an in-flight or submitted transaction boundary, accepts exactly one bound `ActionSent` event from the configured OApp receipt, and never infers policy or execution from mining. A terminal harness session cannot originate a second fixed-authorization action. Only `/api/jobs/:guid` and `/api/deliveries` can produce policy rejection, delivery incident, or execution presentation. Operations polling, including live runtime status, starts only after the same-origin capability gate allows it. Local runtime status is explicitly `NOT_APPLICABLE_LOCAL_FIXTURE`; it does not imply a production lease. The operations workspace does not create a placeholder job for a browser GUID.

The local harness binds both EDR and app to `127.0.0.1`, validates the public owner before startup, rejects that owner if it matches any unlocked harness account, uses an OS-selected EDR port, funds only that supplied address explicitly, keeps ephemeral signer capabilities in process memory, and prints no signer material or database path. Static governance evidence and semantic finality are labeled `LOCAL_POLICY_FIXTURE`; local packet proofs include `LOCAL_EDR_FIXTURE`; external injected mode remains read-only. Browser reload restores no approval state. A post-mining coordinator/store restart rediscovers the original transaction without asking the wallet to send again. A separate durable local-executor store records an ambiguous OApp-delivery incident across reopen and removes it only after exact on-chain execution evidence is observed. The operator-recovery E2E uses five additional ephemeral wallets distinct from the five DVN signer accounts; it proves cryptographic 3-of-5 approval and one real local adapter/OApp recovery path, not independent operators or deployed custody.

Residual risks: GenLayer validator/model correlation, governance source compromise, coordinator compromise, both source or destination RPCs lying consistently, non-atomic multi-call state reads at one block, destination chain/account/nonce failure, signer or recovery-operator implementation compromise, certificate-authority compromise, stale/unrotated pins, missing revocation/OCSP policy, multiple nominal operators under common control, three colluding recovery operators, LayerZero or adapter bugs, finality/API interpretation errors, reservation-triggered denial of service, ambiguous transaction broadcast, fee volatility, malicious browser extensions, local-machine compromise, and general signer/operator unavailability. Direct-mode web and LLM results are mocks; its controlled equality hook does not execute the real semantic comparator, prove live renderer stability, establish model diversity, or demonstrate independent validators. The signer finality attestor uses an injected transaction-witness reader; until an official live adapter is reviewed, its controlled tests do not prove Bradbury response stability or authentication. A compromised authorized coordinator can still choose which otherwise valid request to submit, but it cannot make a conforming signer accept a mismatched v2 witness. Recovery can restore progress but cannot reverse an executed action, prove operator independence, or repair a destination transaction that never reached the chain. A local receipt hash chain is tamper-evident only relative to a previously exported trusted head; unrestricted database administrators can truncate or recompute uncheckpointed history. There is no on-chain recovery governor, HSM enforcement or independently witnessed ceremony. A wallet can lie about displayed calldata; users must verify the configured local OApp and action in their wallet. Loopback is not an authentication boundary on a compromised host. Same-tab restoration retains only a public, capability-bound transaction/GUID locator; it restores no wallet connection, quote, approval, policy result, or authority and cannot follow a different or unverified harness. Source receipt ambiguity and destination intent-before-broadcast prevent unsafe automatic replay but can require manual reconciliation. A semantic `ALLOW` is not proof of source-chain inclusion. Contract `DECIDED` is not off-chain `FINALIZED` and cannot authorize signing. A deterministic pass is not governance authorization. A historical configuration digest proves agreement over decoded observations, not the independence or honesty of the two providers. Runtime status is a same-process self-report, not external monitoring, process-liveness proof, failover, or recovery authorization. Runtime-generated certificates and real local mTLS sockets prove the implementation boundary, not production CA control, revocation, HSM custody, rate-limited ingress, operator independence or separate failure domains.

Rollback: stop each signer daemon first so intake closes and active requests drain before its replay/finality/key owners are closed; certificate rotation constructs a new daemon instance with newly injected capabilities. Stop the local harness to destroy its isolated chain and remove its temporary database. For a deployed system, pause job intake and signer issuance, complete a clean runtime lease release, preserve and externally checkpoint the audit head, remove Sentinel from optional DVNs using OApp owner governance, and rotate DVN signers through an audited adapter migration. Rotate recovery membership through a reviewed manifest ceremony. Because partial council rotation does not change the deployment digest, immediate invalidation of every outstanding proposal requires rotating all five identities or changing a deployment-bound identity; otherwise keep recovery paused until the bounded one-day maximum proposal lifetime has elapsed. Never reuse an old signed bundle after deployment or council changes. Never rewrite finalized decisions; deploy a new policy version and explicitly migrate only future GUIDs. Already executed cross-chain actions are not reversible by Sentinel.
